# Instruction

Этот модуль отвечает за представление и выполнение инструкций виртуального процессора. В проекте инструкция хранится как небольшой объект с кодом операции и тремя аргументами, а затем исполняется функцией `execute()`.

## Что такое инструкция

### Instruction
Структура `Instruction` содержит:
- `opcode` — тип операции;
- `a`, `b`, `c` — аргументы, зависящие от конкретной команды.


## Поддерживаемые операции

В `instruction.h` объявлен enum `Opcode`:
- `OP_LOAD` — чтение из памяти в регистр;
- `OP_STORE` — запись значения регистра в память;
- `OP_ADD` — сложение;
- `OP_SUB` — вычитание;
- `OP_HALT` — остановка программы;
- `OP_JUMP` — безусловный переход;
- `OP_MUL` — умножение;
- `OP_DIV` — деление;
- `OP_CMP` — сравнение;
- `OP_JIF` — переход по условию.

Это базовый набор команд, достаточный для простых программ.

## Функция execute

Функция `execute(Core *core, const Instruction *instruction, Memory *memory, Cache *cache, Cache *l2_cache, size_t program_size, Statistics *stats)` выполняет одну инструкцию.

Её схема работы следующая:
1. сбрасывает состояние ядра в `NORMAL`;
2. выбирает ветку по `instruction->opcode`;
3. проверяет корректность аргументов через чекеры;
4. если всё корректно — выполняет соответствующую операцию;
5. обновляет статистику по количеству операций и ошибок;
6. в конце может перевести ядро в `HALT`, `JUMP` или `ERROR`.

### `OP_LOAD`
Для загрузки значения из памяти:
- проверяется, что регистр назначения допустим;
- проверяется, что регистр адреса допустим;
- считывается адрес из `core->registers[instruction->b]`;
- проверяется, что адрес не выходит за пределы памяти;
- затем значение читается через кэш.

Если используется L2, вызвается `cache_read_word_with_l2()`. Иначе — `cache_read_word()`.

Если чтение не удалось, ядро переводится в `ERROR`, а счётчик ошибок увеличивается.

### `OP_STORE`
Для записи значения в память:
- проверяется индекс регистра адреса;
- проверяется регистр-источник;
- берётся адрес из регистра; 
- проверяется валидность адреса;
- затем значение сохраняется в память через кэш.

Если есть L2, используется `cache_write_word_with_l2()`, иначе — `cache_write_word()`.

### `OP_JIF`
Команда перехода по условию:
- проверяет корректность индекса инструкции;
- сравнивает `instruction->b` с текущим флагом ядра;
- если флаг совпадает, выполняется `core->pc = instruction->a`;
- устанавливается состояние `JUMP`.

То есть это условный переход на другую инструкцию по результату последнего сравнения.

### `OP_JUMP`
Безусловный переход:
- проверяет индекс цели;
- присваивает `core->pc = instruction->a`;
- переводит ядро в состояние `JUMP`.

### `OP_ADD`, `OP_SUB`, `OP_MUL`, `OP_DIV`
Арифметические команды выполняют вычисления над регистрами:
- `ADD` — сложение;
- `SUB` — вычитание;
- `MUL` — умножение;
- `DIV` — деление.

Перед вычислением проверяются:
- целевой регистр;
- два исходных регистра.

Для деления выполняется дополнительная проверка: если делитель равен нулю, ядро переходит в `ERROR` и выводится сообщение.

### `OP_CMP`
Команда сравнения:
- сравнивает значения двух регистров;
- выставляет `core->flag` в `GREATER`, `LESS` или `SAME`;
- увеличивает счётчик проверок.


### `OP_HALT`
Останавливает выполнение программы:
- `core->current_state = HALT`.


## Чекеры

В этом файле так же реализованы валидаторы, которые проверяют корректность аргументов перед исполнением операции. Они нужны, чтобы логика не обращалась к несуществующему регистру или адресу памяти.

### checker_destination
Проверяет, что индекс регистра, куда записывается результат, не выходит за пределы `REGISTERS_COUNT`.

### checker_address_register
Проверяет регистр, который хранит адрес памяти.

### checker_source_register
Проверяет, что регистр, из которого читаются данные, допустимый.

### checker_memory_address
Проверяет, что адрес памяти лежит в диапазоне `[0, MEMORY_SIZE)`.

### checker_instruction_index
Проверяет, что индекс инструкции в программе не выходит за пределы программы.

### checker_condition_register, checker_target_register
Эти функции тоже проверяют валидность регистров, но используются как частные случаи в более общей логике проверки. В текущей реализации они служат формальным контролем корректности входных данных.

## Статистика и диагностика

Во время выполнения функции `execute()` обновляются поля `Statistics`:
- `loads`, `stores`, `adds`, `subs`, `muls`, `divs`, `checks`, `jumps`, `conditional_jumps`;
- `errors` при системных сбоях.
