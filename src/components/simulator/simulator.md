# Simulator

Этот модуль реализует планировщик и цикл выполнения задач на виртуальных ядрах.
## Основные структуры

### Program
`Program` хранит:
- указатель на массив инструкций;
- размер массива.


### Task
`Task` описывает задачу:
- `program` — программа задачи;
- `core_registers` — начальные значения регистров для ядра;
- `state` — состояние задачи (`FREE`, `WORKING`, `DONE`, `TASK_ERROR`, `TASK_TIMEOUT`);
- `stats` — статистика выполнения этой задачи.

### CoreContext
`CoreContext` — это связка из:
- виртуального ядра `Core core`;
- статуса выполнения `task_state`;
- индекса задачи `task_index`;
- L1-кэша `l1_cache`.

Каждое ядро в симуляторе имеет собственный кэш первого уровня.

### Simulator
`Simulator` содержит всё общее:
- массив `cores`;
- массив `tasks`;
- количество задач и ядер;
- индекс следующей задачи;
- общий L2-кэш;
- общую память;
- счётчик тактов.

## Функции

### submin_task
Функция `submin_task(Simulator *sim)` распределяет задачи по свободным ядрам.

Как это работает:
- ищет свободное ядро через `find_free_core`;
- если ядро найдено, берёт следующую задачу;
- сбрасывает состояние ядра через `core_reset`;
- копирует начальные регистры из задачи;
- помечает задачу как `WORKING` и назначает ядру этот task.

Это позволяет симулятору постепенно "поднимать" задачи на вычислительные ресурсы.

### run
Функция `run(Simulator *sim)` запускает главный цикл симуляции.

Что она делает:
1. проверяет корректность входных данных;
2. инициализирует L1 для каждого ядра;
3. инициализирует общий L2;
4. пока есть работа или есть незапланированные задачи, выполняет цикл:
   - назначает задачи;
   - для каждого работающего ядра вызывает `step_core`;
   - увеличивает счётчик глобальных тактов;
5. если превышён лимит `MAX_CYCLES`, переводит активные задачи в `TASK_TIMEOUT`.

По сути, это главный менеджер выполнения всей симуляции.

### step_core
Функция `step_core(CoreContext *context, const Program *program, Memory *memory, Cache *l2_cache, Statistics *stats)` исполняет одну инструкцию для одного ядра.

Что делает:
- проверяет, что ядро реально работает;
- проверяет корректность программы и адреса памяти;
- вызывает `execute()` для текущей инструкции;
- увеличивает статистику по задаче;
- обновляет состояние ядра:
  - если `HALT` - задача завершена;
  - если `ERROR` - ошибка;
  - если `JUMP` - состояние сбрасывается в `NORMAL` после перехода;
  - иначе `pc` увеличивается на 1.

Это основная точка, где одна инструкция превращается в шаг реального исполнения.

### find_free_core
Функция ищет первое ядро в состоянии `FREE`.

Её задача — быстро найти свободный вычислительный слот для новой задачи.

### find_working_cores
Проверяет, есть ли хотя бы одно ядро в состоянии `WORKING`.

Она нужна для условия цикла симуляции: если нет активных ядер и нет новых задач, симуляция может завершиться.
