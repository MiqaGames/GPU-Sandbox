# Config Decoder

Модуль загружает JSON-конфигурацию симулятора, проверяет её и заполняет `SimulatorConfig`. Реализация использует библиотеку cJSON.

## Структуры

`CacheConfig` содержит параметры одного кэша: `sets` (число наборов), `ways` (число линий в наборе) и `words_per_line` (число слов в линии).

`SimulatorConfig` содержит конфигурации `l1` и `l2`, размер основной памяти `memory_size`, максимальный размер программы `max_program_size` и предел числа тактов `max_cycles`.

## Публичные функции

### `config_load_file`

```c
bool config_load_file(const char *path, SimulatorConfig *config, char *error, size_t error_size);
```

Читает непустой файл по указанному пути, выделяет буфер под его содержимое и передаёт JSON в `config_parse_json()`. Путь интерпретируется относительно текущей рабочей директории процесса; функция не выбирает файл конфигурации автоматически. При ошибке возвращает `false` и, если буфер ошибки доступен, записывает в него сообщение.

### `config_parse_json`

```c
bool config_parse_json(const char *json_text, SimulatorConfig *config, char *error, size_t error_size);
```

Разбирает JSON-строку и проверяет версию, параметры обоих кэшей, размер памяти, максимальный размер программы и максимальное число тактов. Результат сначала формируется во временной структуре и копируется в `*config` только после успешной проверки всех полей. При ошибке возвращает `false` и записывает сообщение в буфер ошибки.

## Внутренняя проверка кэша

`read_cache_config()` извлекает из `cache.l1` или `cache.l2` числовые целочисленные значения `sets`, `ways` и `words_per_line`, проверяя их положительность и представимость в `size_t`. `validate_cache_config()` дополнительно требует `sets > 0`, `ways >= 2` и `words_per_line > 0`.

Публичной функции `get_memory_size()` в текущем API нет: поля памяти и лимитов читаются непосредственно в `config_parse_json()`.
